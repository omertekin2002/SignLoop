## Replay and source catalog wire shape

`agentMessages` returned by the gateway now holds only complete tool-call/result pairs. Assistant prose is omitted because the reply's canonical `message` carries it; on the next turn the service sends the replayed pairs and then that canonical content, so the answer reaches the model once and is not clipped twice. Replay stored by earlier gateway releases, which embedded up to 4000 characters of each answer, is accepted and stripped of that prose.

Each `webSources` entry now has an explicit `number`. Citations, `readSources`, and footers use these numbers. When a new page needs room, inherited entries not read during the current turn are retired oldest first, and their numbers are never reused. Earlier releases sent positional catalogs without numbers; those remain valid input, are read as `[index + 1]`, and come back with explicit numbers. Catalogs with duplicate or invalid numbers are dropped. The 64-entry and 16000-character caps apply to the numbered catalog. When numbering legacy entries requires initial pruning, the highest-numbered entry is retained as the allocation watermark; a turn with no new reads therefore cannot lose the counter or reset exhausted IDs. Other inherited entries are still retired oldest first. If a single valid legacy entry would exceed the cap after numbering because JSON escapes expand its content, migration drops its optional snippet while preserving its title, exact URL, and number.

## Dependencies

`undici` moves from 6.27.0 to 6.29.1, matching SignLoop's runtime security patch (`49486d0`) and its lockfile integrity. SignLoop also pins every `undici` in its workspace to 6.29.1 through a root override. The gateway's only other copy is `@ai-sdk/provider-utils`' nested `undici` 7.29.1, which that package requires and loads only for Node-runtime download fetching. Overriding it would be a major-version downgrade, so the gateway adds no override. The patch's other changes (`next`, `axios`, `postcss`, and the `form-data`/`ws` overrides) are not gateway runtime dependencies; `postcss` appears only through the test runner's `vite`.

## Upstream changes not ported

- Private contracts: the contract egress guard, contract-evidence receipts in replies and history bounds, the contract tool note, jurisdiction prompt guidance for contract answers, and Unicode-safe `excerptContract` matching all belong to tools the gateway does not include.
- Model discovery (`model-settings.ts`): SignLoop now lets generation reuse its last successful 60-second `/models` snapshot for one more minute while it refreshes in the background through Next `after()`. The gateway's cache is per configured model, definite results already last five minutes, unknown results last one minute and still attempt primary, and image tools are offered only on a positive result. Reusing stale results would extend how long a removed image model is advertised and would change caller-cancellation caching for little latency gain, so this optimization is not ported.
- Application telemetry and quotas: generation timing hooks, Langfuse content-recording policy, shared chat/analysis admission, RateLimit headers, and usage endpoints. The gateway keeps its own allowlisted logs and per-process concurrency gate and does not enable AI SDK telemetry.
- App and UI modules: WorkOS authentication, saved threads and sessions, chat titles, client NDJSON/error parsing, `chat-history-bounds.ts` as a separate browser module, storage cleanup, OCR/extraction, analysis and evaluations, components, Next.js configuration, and CI.

## Application-specific exclusions

No Next.js/React UI, Clerk or WorkOS authentication, Postgres, contract/project tools, uploads, saved threads, automatic titles, attachment persistence, application admission tables, or Langfuse exporters are imported. The gateway stays stateless and publicly callable. Optional images are returned inline rather than stored in SignLoop attachments.

## Companion client

The companion `otekin` client (`~/Desktop/Grind/otekin`) was updated separately for the `3f830ab` port to retain bounded tool replay/source catalogs, allow the longer agent deadline, compact image history, and save generated images for terminal users. It remains dependency-free and uses non-streaming `/v1/chat`; `--json` preserves the full response. It forwards `agentMessages` and `webSources` as received, so prose-free replay and explicit `number` fields round-trip without client changes, and the canonical `message` footer is always correct.

The companion fix is implemented separately in [otekin PR #4](https://github.com/omertekin2002/otekin/pull/4), commit `cb17c651a5b66cbe62e93391001ea72e515225af`. Its terminal source list (`collectSources` in `lib/chat-format.js`) resolves explicit stable numbers, uses positions only for numberless legacy entries, and keeps the matching titles and terminal hyperlinks after catalog eviction. Missing metadata falls back to the canonical footer; legacy-footer matching consumes each source once and preserves the original footer when numbering is ambiguous. Regression tests cover gapped, high and reordered IDs, legacy and mixed catalogs, partial metadata, and correct hyperlinks.

Installations based on `12b4de8` (version `0.1.8`) still use the old positional lookup (`webSources[number - 1]`), which can pair a citation with another entry's title and URL after eviction. Distribute the updated client before deploying this gateway change. Opening these pull requests does not publish the package or deploy the gateway; the client's existing main-branch workflow publishes a patch release after merge.
